<h2>Choosing Algorithmic Patterns</h2>

<p>
Выбор правильного алгоритмического паттерна — ключевой шаг при решении задач.  
Неправильный выбор приводит к избыточной сложности, медленной работе или невозможности уложиться в ограничения.  
Эта статья систематизирует подход к выбору паттерна и объясняет, какой инструмент применять в зависимости от структуры входных данных и требований задачи.
</p>

<h3>Как подходить к выбору паттерна</h3>

<p>
Алгоритмические паттерны выбирают не по названию задачи, а по её <strong>структуре</strong>:
</p>

<ul>
  <li>какие данные даны (массив, граф, дерево, строка);</li>
  <li>какие операции нужно выполнять (поиск, обновление, подсчёт, оптимизация);</li>
  <li>какие ограничения по времени и памяти;</li>
  <li>есть ли монотонность, подзадачи, пересечения, зависимости;</li>
  <li>нужно ли обрабатывать запросы онлайн или оффлайн.</li>
</ul>

<p>
Ниже — практическое руководство: какой паттерн выбирать в зависимости от типа задачи.
</p>

<hr/>

<h3>1. Когда использовать Two Pointers</h3>

<p>Подходит, если:</p>

<ul>
  <li>дан массив или строка;</li>
  <li>нужны подотрезки, пары, пересечения;</li>
  <li>все элементы обрабатываются монотонно (индексы не откатываются назад).</li>
</ul>

<p><strong>Примеры:</strong> сумма подотрезка, поиск пары с заданной суммой, удаление дубликатов.</p>

<hr/>

<h3>2. Когда использовать Sliding Window</h3>

<p>Используется, если:</p>

<ul>
  <li>нужно найти подмассив с определёнными свойствами;</li>
  <li>свойства можно поддерживать инкрементально (частоты, сумма, количество уникальных);</li>
  <li>окно движется только вперёд.</li>
</ul>

<p><strong>Примеры:</strong> максимальная длина подстроки без повторов, минимальное окно, сумма не превышает K.</p>

<hr/>

<h3>3. Когда использовать Prefix Sums / Difference Array</h3>

<p>Подходят, если:</p>

<ul>
  <li>нужно быстро отвечать на диапазонные запросы;</li>
  <li>нужны массовые обновления диапазонов;</li>
  <li>дан статический массив (без изменений между запросами).</li>
</ul>

<p><strong>Примеры:</strong> сумма на отрезке, количество элементов, разница между префиксами.</p>

<hr/>

<h3>4. Когда использовать Binary Search (в том числе по ответу)</h3>

<p>Используется, если:</p>

<ul>
  <li>есть монотонность (да/нет, можно/нельзя, подходит/не подходит);</li>
  <li>нужно найти минимальный/максимальный параметр;</li>
  <li>функция проверки работает за O(log n) или O(n).</li>
</ul>

<p><strong>Примеры:</strong> минимальная скорость, минимальный радиус, оптимальный порог.</p>

<hr/>

<h3>5. Когда использовать Greedy</h3>

<p>Жадные алгоритмы подходят, если:</p>

<ul>
  <li>локальный оптимум ведёт к глобальному;</li>
  <li>можно доказать корректность выбора;</li>
  <li>нет необходимости пересматривать решения.</li>
</ul>

<p><strong>Примеры:</strong> интервалы, задачи о монетах, сортировка по ключу.</p>

<hr/>

<h3>6. Когда использовать Dynamic Programming</h3>

<p>ДП выбирают, если:</p>

<ul>
  <li>задача разбивается на подзадачи;</li>
  <li>есть перекрывающиеся подзадачи;</li>
  <li>можно определить состояние и переходы;</li>
  <li>нужна оптимизация (минимум, максимум, количество способов).</li>
</ul>

<p><strong>Примеры:</strong> рюкзак, пути в сетке, разбиение строки, ДП по маскам.</p>

<hr/>

<h3>7. Когда использовать DP on Trees</h3>

<p>Подходит, если:</p>

<ul>
  <li>дано дерево;</li>
  <li>нужно вычислять значения по поддеревьям;</li>
  <li>нужны rerooting‑техники (пересчёт корня).</li>
</ul>

<p><strong>Примеры:</strong> количество путей, максимальные суммы, расстояния.</p>

<hr/>

<h3>8. Когда использовать Graph Traversal (BFS/DFS)</h3>

<p>Используется, если:</p>

<ul>
  <li>дан граф или сетка;</li>
  <li>нужно найти компоненты, пути, циклы;</li>
  <li>нужно проверить достижимость.</li>
</ul>

<p><strong>Примеры:</strong> поиск пути, топологическая сортировка, проверка связности.</p>

<hr/>

<h3>9. Когда использовать Shortest Paths</h3>

<ul>
  <li><strong>Dijkstra</strong> — нет отрицательных рёбер;</li>
  <li><strong>Bellman–Ford</strong> — есть отрицательные рёбра;</li>
  <li><strong>Floyd–Warshall</strong> — все пары вершин, маленький граф.</li>
</ul>

<p><strong>Примеры:</strong> маршрутизация, графы дорог, минимальные стоимости.</p>

<hr/>

<h3>10. Когда использовать DSU (Union-Find)</h3>

<p>Подходит, если:</p>

<ul>
  <li>нужно объединять компоненты;</li>
  <li>нужно быстро проверять связь;</li>
  <li>граф динамически растёт.</li>
</ul>

<p><strong>Примеры:</strong> MST (Kruskal), динамическая связность, кластеризация.</p>

<hr/>

<h3>11. Когда использовать Backtracking</h3>

<p>Используется, если:</p>

<ul>
  <li>нужно перебрать варианты;</li>
  <li>есть ограничения, позволяющие отсекать ветви;</li>
  <li>размер входа мал (обычно n ≤ 20).</li>
</ul>

<p><strong>Примеры:</strong> Sudoku, перестановки, комбинации, N‑ферзей.</p>

<hr/>

<h3>12. Когда использовать Divide and Conquer</h3>

<p>Подходит, если:</p>

<ul>
  <li>задача естественно делится на части;</li>
  <li>результаты частей можно объединить;</li>
  <li>рекурсивная структура очевидна.</li>
</ul>

<p><strong>Примеры:</strong> merge sort, quick sort, FFT.</p>

<hr/>

<h3>13. Когда использовать Meet-in-the-Middle</h3>

<p>Используется, если:</p>

<ul>
  <li>задача экспоненциальная;</li>
  <li>можно разделить вход пополам;</li>
  <li>2^(n/2) приемлемо, а 2^n — нет.</li>
</ul>

<p><strong>Примеры:</strong> сумма подмножеств, перебор состояний.</p>

<hr/>

<h3>14. Когда использовать Bitmask Techniques</h3>

<p>Подходит, если:</p>

<ul>
  <li>n ≤ 20–22;</li>
  <li>нужно работать с подмножествами;</li>
  <li>нужно кодировать состояния компактно.</li>
</ul>

<p><strong>Примеры:</strong> ДП по маскам, перебор подмножеств, графы малой размерности.</p>

<hr/>

<h3>15. Когда использовать Mo’s Algorithm</h3>

<p>Используется, если:</p>

<ul>
  <li>есть оффлайн‑запросы на массиве;</li>
  <li>операции добавления/удаления элемента быстрые;</li>
  <li>нужно отвечать на запросы диапазонов.</li>
</ul>

<p><strong>Примеры:</strong> количество уникальных на отрезке, частоты, offline RMQ.</p>

<hr/>

<h3>Заключение</h3>

<p>
Выбор алгоритмического паттерна — это умение распознавать структуру задачи.  
Чем больше паттернов вы знаете, тем быстрее сможете определить подходящий инструмент.  
Эта статья служит картой, помогающей выбрать правильный путь при решении задач любой сложности.
</p>
